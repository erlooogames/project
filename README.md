# Telegram-бот модерации

Бот для групп на Python 3.11+, aiogram и SQLite. Он работает через long polling. Команды принимаются на русском и английском независимо от языка ответов группы.

## Настройка Telegram

1. Отправьте `/newbot` боту @BotFather. Назовите бота, выберите username и сохраните выданный токен. Если токен уже был опубликован, отзовите его через `/revoke` и используйте новый.
2. В @BotFather выберите `/setprivacy` → вашего бота → **Disable**. Если бот уже в группе, удалите его из группы и добавьте заново для применения изменения. Для антиспама, огоньков, фильтра ссылок и очистки боту нужен поток обычных сообщений.
3. Добавьте бота в **супергруппу** и назначьте администратором. Дайте права **блокировать участников** для банов, мутов, киков и автоматических наказаний, а также **удалять сообщения** для очистки, фильтра ссылок и удаления команд. Обычная группа поддерживает варны и функции без ограничения доступа. Чтобы использовать муты, баны и кики, переведите её в супергруппу средствами Telegram.
4. Первую привязку владельца выполните до выдачи доступа модераторам. Запустите бота с секретным `OWNER_SETUP_CODE`. Аккаунт **@UnixX_Prime** должен отправить в личные сообщения боту `/claim <код>`. Бот сохранит числовой Telegram ID в SQLite. С этого момента смена username не влияет на полномочия. После привязки удалите `OWNER_SETUP_CODE` из окружения. Код привязки можно создать командой ниже.

```bash
python -c 'import secrets; print(secrets.token_urlsafe(32))'
```

Привязка выполняется один раз. Если хранилище потеряно, остановите бота и восстановите доверенную резервную копию базы с записью владельца. Команды для сброса или переоформления владельца в Telegram нет. Пользуйтесь отдельными базами для тестового и рабочего ботов.

## Запуск локально

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python main.py
```

Между копированием шаблона и запуском заполните `.env`. В окружении хостинга задайте те же имена переменных в панели. Значения из уже заданного окружения имеют приоритет над `.env`.

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен от BotFather. Обязателен. |
| `OWNER_SETUP_CODE` | Секрет от 24 символов без пробелов для первичной привязки. |
| `DB_PATH` | Путь к SQLite. По умолчанию `data/moderation.sqlite3`, на Bothost используйте `/app/data/moderation.sqlite3`. |
| `ITUNES_COUNTRY` | Двухбуквенный код витрины iTunes, по умолчанию `US`. |
| `LOG_LEVEL` | Уровень логов, по умолчанию `INFO`. |

Используйте один экземпляр long polling на токен. Остановите локальный процесс перед запуском того же токена на хостинге. Для SQLite нужен Python с SQLite 3.35+.

## Развёртывание на Bothost

1. В панели Bothost нажмите **Создать бота**, выберите платформу **Telegram** и среду **Python / aiogram**. Введите перевыпущенный токен в поле **Bot Token**. Он будет доступен как `BOT_TOKEN`.
2. Вставьте в **Git URL репозитория** `https://github.com/erlooogames/project.git`. Укажите точное имя ветки с кодом. Для проверки PR используйте `codex/telegram-moderation-bot`, после слияния переключитесь на `main`.
3. В разделе **Переменные окружения** задайте `OWNER_SETUP_CODE` и `DB_PATH=/app/data/moderation.sqlite3` перед первым запуском. При доступном выборе версии используйте Python 3.11 или новее. Bothost установит `requirements.txt`. Точка входа — `main.py`, команда запуска — `python main.py`.
4. Запустите бота и проверьте в логах строку `Start polling`. Выполните `/claim` в личке и проверьте команды в отдельной тестовой супергруппе.
5. Перед переходом на платный тариф сделайте копию SQLite и проверьте, что новый экземпляр использует её в `DB_PATH`. Бот рассчитан на один процесс, одну SQLite-базу и ограниченные кэши. Фоновый цикл обрабатывает истечение наказаний без внешнего планировщика.

[Быстрый старт Bothost](https://bothost.ru/docs/getting-started) · [Ветки Git](https://bothost.ru/docs/repository-branch-deploy) · [Переменные окружения](https://bothost.ru/docs/environment-variables)

### SQLite и резервные копии

Bothost документирует `/app/data` как папку, сохраняемую при перезапусках и обновлениях из Git. Проверьте сохранность данных на своём тарифе после пробного перезапуска. Если `DB_PATH` указывает на временную файловую систему контейнера, пересборка или перенос могут удалить запись владельца, настройки, варны, журнал и огоньки. На другом хостинге подключите постоянный том и задайте путь к файлу на этом томе.

SQLite в режиме WAL пишет в соседние файлы. Для живой базы используйте SQLite Online Backup или остановите бота перед копированием. Пример создания согласованной копии из терминала Bothost:

```bash
python -c 'import sqlite3; src = sqlite3.connect("/app/data/moderation.sqlite3"); dst = sqlite3.connect("/app/data/moderation-backup.sqlite3"); src.backup(dst); dst.close(); src.close()'
```

Скачайте копию из файлового менеджера и храните её в закрытом внешнем хранилище. Для восстановления остановите бота, переместите старую базу вместе с её `-wal` и `-shm` в отдельное место, положите копию по пути `DB_PATH` и запустите бота. Не размещайте базы, бэкапы, токены или коды привязки в GitHub. [Хранение баз данных на Bothost](https://bothost.ru/docs/database-storage)

## Команды

| Русская | English | Аргументы |
| --- | --- | --- |
| `!мут` | `!mute` | Срок, целевой ID и причина |
| `!анмут` | `!unmute` | Целевой ID и причина |
| `!бан` | `!ban` | Срок, целевой ID и причина |
| `!разбан` | `!unban` | Целевой ID и причина |
| `!варн` | `!warn` | Срок, целевой ID и причина |
| `!снять варн` | `!unwarn` | Последний активный варн у цели или конкретный `#ID` |
| `!кик` | `!kick` | Целевой ID и причина |
| `!варны` | `!warns` | Активные варны и их ID |
| `!история` | `!history` | Последние 8 варнов |
| `!наказания` | `!punishments` | Последние 8 записей журнала |
| `!очистить` | `!purge` | От 1 до 100 сообщений |
| `!антиспам` | `!antispam` | Вкл/выкл, порог и срок мута |
| `!ссылки` | `!links` | Вкл/выкл |
| `!приветствие` | `!welcome` | Вкл/выкл, текст |
| `!музыка` | `!music` | Название трека или исполнитель |
| `!огонек` / `!огонёк` | `!streak` | Текущая и рекордная серия |
| `!огоньки` | `!streaks` | Топ-10 активных серий |
| `!статистика` | `!stats` | Содержательные сообщения и их авторы |
| `!настройки` | `!settings` | Настройки группы |
| `!помощь` | `!help` | Короткий гайд в группе или в личке бота |

Длительности задаются как `м 30` (минуты), `д 7` (дни), `н 2` (недели), либо `m`, `d`, `w` с числом. Диапазон от 1 минуты до 365 дней. `навсегда`, `perm` и `permanent` задают постоянный мут, бан или варн.

- `!мут м 30` ответом на сообщение. `!mute м 15 123456789 флуд` по ID. Явный положительный ID имеет приоритет над ответом. Причина необязательна. Если причина в ответе начинается с числа, используйте `--`, например `!mute m 15 -- 2 одинаковых сообщения`.
- `!бан д 7`, `!ban д 3 123456789` и `!warn perm 123456789`. Для временных мутов и банов бот передаёт `until_date`. При истечении он проверяет состояние Telegram и снимает сохранившееся ограничение, если его срок совпадает с записанным. Разбан позволяет вернуться в группу по приглашению или ссылке.
- `!unwarn 123456789` снимает последний активный варн пользователя. `!снять варн 123456789 #12` или `!unwarn #12` снимает конкретный варн в этом чате. Можно ответить на сообщение пользователя командой `!unwarn #12`.
- `!warns`, `!history`, `!punishments` и `!streak` без цели показывают данные автора команды. Для просмотра чужих варнов и наказаний нужны полномочия администратора. `!streak` других участников доступна всем.
- Администратору нужны соответствующие права для наказаний и очистки. Команды модерации принимаются от личного профиля. Бот защищает владельца бота и создателя группы. Только владелец бота может выдавать и снимать варны другим администраторам. Действия через Telegram всё равно зависят от прав и возможностей самого бота.

После получения трёх ещё не использованных действующих варнов выдаётся один мут на 24 часа. Каждая тройка используется только раз. Использованные варны остаются активными до истечения или снятия. Уже действующий мут автоматикой не продлевается. Если порог достигнут в обычной группе, бот сохранит варны, а автоматический мут сможет применить в супергруппе.

## Настройки группы

По умолчанию ответы на русском, часовой пояс `Europe/Kyiv`. Антиспам, фильтр ссылок, приветствие и статистика выключены. Огоньки, музыка, история, очистка и удаление успешных команд включены. Настройки каждой группы хранятся в SQLite.

| Русская | English |
| --- | --- |
| `!антиспам вкл` / `выкл` | `!antispam on` / `off` |
| `!антиспам лимит 5 10` | `!antispam limit 5 10` |
| `!антиспам мут м 30` | `!antispam mute m 30` |
| `!ссылки вкл` / `выкл` | `!links on` / `off` |
| `!приветствие вкл` / `выкл` | `!welcome on` / `off` |
| `!приветствие текст Привет, {name}!` | `!welcome text Welcome to {chat}, {name}!` |
| `!настройки язык en` | `!settings language en` |
| `!настройки пояс Europe/Kyiv` | `!settings timezone Europe/Kyiv` |
| `!настройки лимит 3` | `!settings warnlimit 3` |
| `!настройки варнмут д 1` | `!settings warnmute d 1` |
| `!настройки история вкл` | `!settings history on` |
| `!настройки очистка вкл` | `!settings purge on` |
| `!настройки статистика вкл` | `!settings stats on` |
| `!настройки музыка вкл` | `!settings music on` |
| `!настройки огоньки вкл` | `!settings streaks on` |
| `!настройки команды вкл` | `!settings deletecommands on` |

- Антиспам по умолчанию реагирует на шестое сообщение за 10 секунд или на третье одинаковое сообщение в этом промежутке. Автомут по умолчанию длится 30 минут. Боты, администраторы и владелец бота исключены.
- Включённый фильтр тихо удаляет ссылки из сообщений и их правок у обычных участников. Приветствие отправляется один раз на событие входа и поддерживает `{name}` и `{chat}`.
- Огонёк растёт по календарным дням чата за текст с буквами или цифрами либо содержательное вложение. Команды, сообщения ботов, повторы и сообщения, пересёкшие порог флуда, не засчитываются. Топ показывает серии, действующие сегодня или со вчерашнего дня. Статистика накапливается только после включения.
- Для очистки бот записывает ID последних 200 доступных ему сообщений в каждой группе. `!purge` выбирает сообщения текущей темы младше 48 часов. Telegram может пропустить уже удалённые сообщения. История, недоступная боту, в очистку не попадает.
- Поиск обращается к iTunes Search API и показывает ссылку на Apple Music/iTunes и, при наличии, ссылку на превью. Аудио на сервер не скачивается. Запросы ограничены по частоте.
- Выключение истории скрывает команды просмотра истории и журнала. Варны и журнал модерации продолжают записываться. Выключение огоньков или статистики приостанавливает их подсчёт.

## Проверка

```bash
python -m unittest discover -s tests -v
python -m compileall -q main.py bot tests
```

Тесты используют временную SQLite и тестовую сессию Telegram. Для проверки на Bothost отправьте в тестовой супергруппе `!help`, затем выдайте мут ответом и снимите его по ID. Повторите с `!ban` и `!unban`, выдайте три варна тестовому участнику, проверьте `!warns` и `!history`. Дайте минутному муту истечь, проверьте антиспам, огонёк и поиск трека. Перезапустите бота в панели и убедитесь, что настройки и варны остались.
